# Web App + Portfolio Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A password-protected Next.js app for the agent (runs, review, tracker, profile builder) plus a public, backend-free demo that replays recorded runs.

**Architecture:** Next.js (`frontend/`) proxies `/api/*` to FastAPI, so the session cookie is first-party and no secret reaches the browser. Runs execute in background threads with progress. Every screen renders from the API types through an `AgentClient` interface with a live (`HttpClient`) and a demo (`DemoClient`) implementation.

**Tech Stack:** FastAPI, LangGraph, pytest (backend); Next.js 16, React 19, TypeScript, Tailwind 4, Vitest + Testing Library, Playwright, openapi-typescript (frontend).

**Spec:** `docs/specs/2026-11-15-web-app-design.md`

## Global Constraints

- No API key, password, session secret or real profile data in git, in the frontend bundle, or in demo fixtures.
- Backend tests never call an LLM; frontend tests never need a running backend.
- Every protected endpoint requires the session cookie; only `/health` and `/auth/*` are open.
- Profile builder only organises what the user wrote; unsupported numbers/orgs/dates are flagged, not kept silently.
- Docs (README, CLAUDE.md, CHANGELOG, `docs/architecture.md`, `frontend/README.md`) updated in the same commit as the change.
- Frontend look: portfolio tokens — paper `#f4f1ec`, ink `#1a1a18`, terracotta `#9c4530`, muted `#6b6b64`; Playfair Display / Inter / JetBrains Mono.

## Review Focus

1. Login brute force → after 5 failures from one IP, further attempts get 429 with a growing wait. *(Task 1 test)*
2. Resuming a run while it is still running → 409, state untouched. *(Task 2 test)*
3. Server restarted mid-run → run shows `error` ("interrupted") and Retry finishes it. *(Task 2 test)*
4. Profile draft containing a number/organisation the user never wrote → flagged in the review screen. *(Task 4 test)*
5. Demo build with a real profile → recorder refuses; fixture test asserts only the sample candidate appears. *(Task 11 tests)*

### Task 1: Single-user auth

**Files:** Create `backend/app/auth.py`, `backend/tests/test_auth.py`; Modify `backend/app/config.py`, `backend/app/main.py`, `backend/tests/conftest.py`, `backend/tests/test_api.py`, `.env.example`.

**Interfaces:**
- Settings: `app_password: SecretStr | None`, `session_secret: SecretStr | None`, `session_days: int = 30`.
- `auth.make_token(now: float) -> str`, `auth.verify_token(token: str, now: float) -> bool` (HMAC-SHA256 over expiry with `session_secret`); `auth.require_session` FastAPI dependency (401 if missing/invalid, 503 if `app_password` unset); `auth.router` with `POST /auth/login {password}` (204 + cookie `session`, HttpOnly, SameSite=Lax, Secure unless host is localhost/127.0.0.1), `POST /auth/logout`, `GET /auth/me` → `{authenticated: bool}`.
- Throttle: per client IP, after 5 consecutive failures wait `2**(n-5)` s (cap 300) → 429 with `Retry-After`; success resets.
- Test fixture `client` logs in with a test password.

- [ ] Tests: `test_login_sets_httponly_cookie`, `test_wrong_password_401`, `test_protected_endpoints_require_session` (runs, applications, profile), `test_health_is_public`, `test_tampered_or_expired_token_rejected`, `test_throttle_after_five_failures`, `test_no_password_configured_503`, `test_logout_clears_cookie`.

### Task 2: Background runs, progress, lock, restart recovery, run list

**Files:** Modify `backend/app/runs.py`, `backend/app/main.py`, `backend/app/api/models.py`, `backend/app/cli.py`, `backend/app/db.py`; Tests `backend/tests/test_runs.py`, `backend/tests/test_api.py`.

**Interfaces:**
- `Runs(graph, executor: Executor | None = None)`; `None` → run inline (CLI, most tests); API uses a module-level `ThreadPoolExecutor(max_workers=4)`.
- Execution uses `graph.stream(payload, cfg, stream_mode="updates")`; `self._step[run_id]` = node about to run / last completed; cleared when done.
- `RunView.status` adds `"running"` while in flight; `RunView.step: str | None`; `RunView.created_at`.
- `Runs.answer/retry` raise `Busy` while in flight → API 409.
- Restart recovery: snapshot has `next`, no interrupt, no error, not in flight → `status="error"`, `error="Interrupted (server restarted). Retry to continue."`; `retry` allowed.
- `runs` table (`run_id`, `created_at`) written on start; `Runs.list(limit=20) -> list[RunSummary]` (`run_id, created_at, status, company, title, fit_score`); `GET /runs`.
- API: `POST /runs` → 202, `/resume`, `/retry` → 202.

- [ ] Tests: `test_start_returns_running_then_settles` (threaded executor, poll), `test_progress_step_reported` (blocking fake node), `test_resume_while_running_409`, `test_interrupted_run_is_retryable`, `test_list_runs_newest_first`; adapt API tests to poll until settled.
- [ ] Commit `feat(api): background runs with progress and run list`.
